### Tab unification decision (not done tonight)

**Do not merge look/cast/wardrobe/tier into one class this pass.**

- look / cast / cast-sub / wardrobe CSS is ~byte-identical (wardrobe is an unmerged copy of the look/cast group). That *is* a clear CSS win later: add wardrobe to the existing grouped selector, or rename all four to `.tab` / `.tabs`.
- Renaming to `.tab` is **not** CSS-only: templates (`_album_look_form.html`, `_playlist_card.html`, …) and four JS click handlers in `app.js` (look / wardrobe / cast / cast-sub) hard-code the class names. Tier/family handlers are separate and should stay separate.
- **tier-tab** and **family-tab** intentionally differ (accent, radius). Keep them as modifiers or siblings, not the same base as look-tabs.

**Parent follow-up (small):**

1. CSS-only: fold `.wardrobe-tab(s)` into the existing `.look-tab, .cast-tab, .cast-subtab` selectors (zero HTML/JS change).
2. Later rename: `class="tab look-tab"` → then drop the long names once JS uses `.tab` + `data-*` only.
3. Optional shared helper in JS for “activate tab, hide sibling panels” (four nearly identical click blocks ~3009–3055 and tier/family ~544–568).

## 2. Other duplication worth knowing

- **`.icon-btn` defined twice** (lines ~110 and ~1703): first is smaller generic; second wins for `button`/`a`. Collapse to one definition.
- **JS tab handlers** copy-paste: look / wardrobe / cast / cast-sub / tier / family all do active class + panel `hidden` toggle with slightly different scoping.
- **Delete confirms** in `app.js`: many `closest(".delete-*")` branches with the same confirm pattern — not a CSS issue; candidate for one delegated map later.
- **Folds:** caret unification already exists; new disclosures should use `details.disclose` or `song-fold` instead of inventing another class that must join the long selector list.
